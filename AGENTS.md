# Working in this Jac project

This is a [Jac](https://www.jaseci.org/) project. Jac's syntax has evolved and
is easily confused with Python or JSX -- before writing or editing `.jac`
files, consult the reference guides bundled with the compiler.

## Reference guides

The `jac` CLI ships curated reference guides ("Agent Skills") -- the
authoritative spec for writing correct, idiomatic Jac:

- `jac guide` -- list every available guide
- `jac guide <name>` -- print a guide (e.g. `jac guide jac-types`)
- `jac guide --search <keyword>` -- find guides by topic
- `jac guide --json` -- machine-readable output for tooling

Start with `jac guide jac-core-cheatsheet` and `jac guide jac-types`.

**Install them once instead of remembering to ask.** All 37 are Claude Code
Agent Skills already -- each has the `name`/`description` frontmatter -- so
exporting them puts them where an agent loads the right one on its own:

```bash
jac guide --export ~/.claude/skills
```

The ones that matter for the web console are `jac-cl-components`,
`jac-cl-styling`, `jac-cl-js-interop` and `jac-fullstack-patterns`.

## Ask the compiler, not grep

`jac code` answers structural questions the compiler already knows:

- `jac code map walker` -- every walker archetype
- `jac code symbol Diagnose` -- where a symbol is defined and used
- `jac code walkers HwNode` -- walkers whose entry points traverse a node type
- `jac code diag` -- structured errors and warnings as JSON

## Pitfalls this project actually hit

Written down because each one cost a session. Full accounts in
`docs/HANDOFF.md` §9.

- **`node` is a reserved word everywhere, not just in native code.** Using it
  as a component parameter (`def:pub Row(node: NodeView, ...)`) is `E0013`,
  and the *client build does not fail on it* -- it emits the markup and
  silently discards every `impl` body, so handlers compile to
  `async function boot() {}` and nothing ever calls a walker. Only
  `jac guide jac-native` documents the restriction, and only as a native-code
  rule. Run `jac check` on `.cl.jac` files; it is the only thing that catches
  this.
- **Python string methods do not survive client lowering.**
  `", ".join(items)` becomes a method dispatch on a string primitive and
  throws a non-`Error` value, which then blanks the page via the
  ErrorBoundary. `jac guide jac-cl-js-interop` uses the JS-style receiver form
  (`items.join(sep)`) throughout -- follow it.
- **A scoped stylesheet must be `Comp.style.css` in source.** The compiler
  emits `import "./Comp.css"` as its *output* name; naming the source that
  stops the pairing and ships an unstyled page with a green build. In this
  project the annex route does not work at all (the compiler never copies the
  file into the tree Vite reads), so the stylesheet lives at
  `assets/console.css` and is imported through `@jac-client/assets`.
- **`jac check` is stricter than `jac run`.** `src/jacos.jac` has always
  failed it for harmless reasons; do not "fix" the CLI in response. Hard
  `error[...]` codes in new code are real.

## Validate your work

- `jac check <file>` -- type-check and lint. Compiler diagnostics link to the
  relevant guide; follow the `-> run 'jac guide ...'` hints.
- `jac run <file>` -- execute a Jac script.
- `jac start --dev main.jac` -- start a fullstack app or service in dev mode
  (hot-reload for client files; restart for server changes). Use this instead
  of `jac run` for apps.
- `jac browse <action>` -- QA a running app in a headless browser:
  `jac browse open localhost:8000`, then `snapshot` (accessibility tree with
  `@e1`-style refs), `click @e5`, `fill '#email' user@example.com`, `screenshot`, `close`.
  Needs Chrome on `PATH` or `JACBROWSER_CHROME` set.

When a client build fails, set `debug = true` under `[plugins.client]` in
`jac.toml`. Without it the startup log says only that the build failed; with
it you get the raw Rollup message, which is how the unresolved-stylesheet
error was finally read. Turn it back off -- it prints a warning banner.
